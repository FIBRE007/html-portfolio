What this demo actually does

This is a self-contained browser prototype: RFID capture, face matching and geofencing all run on this device, and records are kept in local storage so there's something to click through without a server. RFID and face recognition are each independent, admin-toggleable check-in methods here — with both on, either one alone is enough — so a school can start with just RFID, add face recognition later, or run both side by side for people who prefer one over the other. A real school deployment needs the pieces below.

  • RFID Here, a USB HID card reader "types" the UID into a focused text field. In production the kiosk should be a locked-down device that forwards the UID to a backend over an authenticated connection, which checks it against the roster server-side — a client can't be trusted to self-report "this card is valid."
  • Face recognition Runs client-side with face-api.js. Checking in via RFID compares against one enrolled descriptor (verification); checking in via face alone matches the live capture against every enrolled descriptor (identification), which doesn't scale well past a few hundred people run entirely in the browser. A production system should re-verify server-side, add liveness detection (blink/challenge) to resist photo/video spoofing, and store descriptors encrypted rather than in local storage.
  • Geofencing Uses the browser Geolocation API and a Haversine distance check against a configured center point. Device GPS can be spoofed or inaccurate indoors, so production systems combine it with network-level signals — school WiFi SSID/BSSID, a fixed kiosk IP range, or BLE beacons — and make the final accept/reject decision on the server, not the client.
  • Parent notifications Simulated here (or sent via EmailJS if you supply credentials in Settings). Production would have the backend call a transactional email API (SES/SendGrid) and a push service (FCM/APNs) so delivery is logged, retried, and not dependent on the kiosk's browser tab staying open.
  • Mobile application The Parent Dashboard page is an installable PWA — "Add to Home Screen" gives parents an app-like icon that shows attendance and notification history offline. A production version would be a native/React Native app that subscribes to real push notifications from the backend described above, instead of reading local storage.
  • Data storage Everything here lives in this browser's local storage, so the kiosk and the parent dashboard only share data if opened on the same device. Production needs a shared database (e.g. Postgres) behind an authenticated API so every device sees the same records.
